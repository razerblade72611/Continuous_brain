# G1-COMPOSITION-RETENTION-v1 — PROPOSED

This is a **proposal**, not approval and not an executable scientific gate.

G0 closed six isolated requalifications with PASS on fresh DEV families. G1 asks the next question: when those same six mechanisms are simultaneously bound into one `UnifiedRuntime`, does each retain the full causal/admission behavior encoded by its own frozen evaluator?

The machine-readable preregistration is `registry/g1_retention_v1.json`. It freezes the six mechanism identities, their verified G0 result hashes, each evaluator's complete required check-key set, proposed fresh DEV-family sizes/ranges, stop rules, and the all-six retention decision rule.

Important constraints:

- G1 may include only the six G0-PASS mechanisms in this version.
- v0.23, v0.24, and v0.28 are excluded.
- Every run must have all six mechanisms bound through audited adapters/state codecs; no stand-ins.
- The original check semantics may not be weakened or replaced by proxy metrics.
- No proposed G1 DEV family is registered in this artifact.
- A scientific G1 runner remains locked until David explicitly approves this preregistration and a later artifact freezes the adapter/binding hashes.

A mechanism-level PASS requires the full frozen check vector to be present and true, the evaluator/admission field to be true, all six mechanisms to have been bound, and all provenance checks to remain intact. A valid completed false check is a scientific FAIL. Missing checks, broken bindings, missing results, source/provenance changes, or process failures are BLOCKED/INFRASTRUCTURE_FAILURE, not scientific FAIL.
